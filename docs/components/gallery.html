Theme Roles

Material-compatible roles mapped to Neptune. and white-label bank tokens. Components read roles, not raw brand colors.

Color rolesWhite labelKMP theme
  • Primary maps to bank identity and selected state.
  • Secondary supports operations without competing with primary.
  • Tertiary is the Neptune. signature accent and must stay rare.
  • Status colors stay protected from bank branding.
KMP Compose
val bankTheme = SignalColorDefaults.whiteLabel(
    primary = Color(0xFFA71930),
    secondary = Color(0xFF07315F),
    accent = Color(0xFFC89B3C),
    ink = Color(0xFF071C2E)
)

SignalTheme(colors = bankTheme) {
    BankingApp()
}

Account Patterns

Reusable account carousel, opened account header, and account list. Compact rows use semantic identifiers, while detail headers show full grouped values.

CarouselListDetail stage
  • Home may use a carousel, but the accounts page should show all accounts as a clear list.
  • Account detail uses `DetailStage` so the opened surface carries the selected account color forward.
  • Copy/share actions belong beside the exact IBAN or alias value.

SignalAccountCarousel(

    onOpenDetails = onOpenAccount

SignalAccountList(

StoreCategoriesValue selector

Identity and Consent

OpenWave and NPT Alias patterns distinguish customer identity, read-only data access, recurring payment mandates, and one-time approvals.

NPT AliasOpenWaveConsent scope
  • Data access and payment mandates are separate objects.
  • One-time approvals show amount, merchant, alias, account, expiry, and reference before approval.
  • Consent and mandate IDs are critical values and never use vague truncation.
KMP Compose
SignalConsentOverview(
